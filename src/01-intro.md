# 1. 引言

## 1.1 背景与动机

Rust 的类型系统和借用检查能够预防大量内存安全问题，但内核仍需要使用 unsafe 代码完成底层内存管理、硬件访问和执行上下文切换。这些代码必须自行维护安全条件，编译通过并不能保证这些条件始终成立。

普通应用通常依赖操作系统提供有效的地址空间、内存分配和线程执行环境，而内核需要自行建立并维护这些条件。因此，内核中的内存错误不仅可能来自一次错误的 Rust 访问，也可能来自更早的页回收、地址映射或执行上下文操作。

KMiri 的动机是让这些内核操作及其后续 Rust 执行能够接受动态检查，在保留 Miri 检查能力的同时，发现单独测试一个函数时难以暴露的对象交互和状态变化问题。

**为何普通 Miri 不足以覆盖内核场景**

Miri 执行 Rust 的 MIR，同时记录这块内存属于哪个对象、哪些字节写过、哪个指针有权访问，以及有没有借用还活着。它看得见的普通 Rust 操作会同时更新这些记录，所以记录和实际字节一致。

内核有两类操作会打破这种一致。一类不在 MIR 里，例如用汇编改页表或栈指针。另一类虽然是 Rust 读写，但地址来自内核自己管理的物理页，Miri 没有这些页的分配和生命周期记录。前者通常让执行停住；如果让执行继续而不更新记录，就会漏报或误报。后者也常常因为地址没有记录而停住；只补字节、不补记录，同样会漏报或误报。

KMiri 要做的是：对选定的这些操作，在改变实际字节或执行位置的同时更新上述记录，让 Rust 原来的检查继续有效。

How-如何实现？存不存在一种kmiri的设计，能够接入不同的rust内核里面？
第一种是内核主动报告事件。内核在分配页、修改映射或切换线程时调用一小套接口，解释器按照这些事件更新自己的记录。Asterinas 的现有设计属于这种。它能表达页和线程，但内核必须改到真的发出这些事件。

第二种是尽量执行内核原来的 Rust 代码，只在解释器过不去的地方做薄桥接。BlueOS 和TockOS目前走的是这种。

## 1.2 问题定义

[明确本文要解决的问题：普通 Miri 缺少页状态、页表、线程调度、SMP/CPU-local 等内核执行语义。]

**如何在尽量保留内核原有代码的情况下，让内核自己管理的内存和执行状态成为 Miri 能够理解和检查的对象？**

具体需要回答三个问题：

* **内核管理的内存如何被检查？** 内核自行分配物理页、建立映射，并在这些地址上创建和回收 Rust 对象。解释器需要知道这些对象的范围、生命周期及不同地址之间的对应关系。例如，某个对象已经被内核释放，但所在的大块内存仍然存在，解释器能否识别之后的访问属于释放后使用？
* **内核管理的执行过程如何被检查？** 内核自行调度线程、切换栈，并访问 CPU-local 数据。解释器需要理解这些操作对执行上下文和并发关系的影响，才能检查后续访问，而不是只让程序继续运行。
* **这些能力如何适用于不同内核？** 不同内核的分配器、调度器、架构接口和构建方式不同。需要研究哪些信息可以从原有执行中识别，哪些需要额外提供，以及如何避免每接入一个内核就重新修改解释器。即存不存在一种kmiri的设计，能够接入不同的rust内核里面？

## 1.3 目标与非目标

**目标**

* **保留检查能力。** 内核操作接入解释器后，仍能对相关 Rust 代码进行内存边界、初始化、指针有效性、借用及数据竞争检查；不能通过关闭检查或忽略关键操作来实现“跑通”。
* **降低跨内核接入成本。** 优先研究从内核原有执行中识别必要信息的方法，尽量减少内核侧修改，并明确共享机制与内核专用适配的边界。是否能够做到、哪些操作仍需额外对接，须通过不同内核的实验验证。
* **检查真实内核路径。** 支持执行内核原有的内存管理和调度代码，包括必要的初始化与操作序列，使检查能够覆盖单个函数之外的对象交互和状态变化。

**非目标**

* [例如：不模拟完整硬件设备与外设行为]
* [例如：不替代 QEMU 等机器仿真器]

## 1.4 术语与缩写

* MIR：Rust 编译器交给 Miri 执行的一层表示。函数被变成赋值、调用、返回等操作后，Miri 逐条执行它们，并同时更新对象、初始化、指针权限和借用记录。
* UB：未定义行为，即 Rust 没有为其规定结果的行为。释放后使用、越界、读取未初始化内存，以及违反借用或指针权限，都是这里所说的 UB。
* Pseudo Physical Memory：当前实现中的伪物理内存。解释器预留一块按页管理的地址区域，用来表示内核的物理地址，并把这些地址对应到 Miri 的对象和字节记录。
* CPU-local：属于单个 CPU 的数据，不是某条线程私有，也不是所有 CPU 共享。当前实现会为模拟出来的 CPU 准备这种存储。
